# tknr1 - 障害福祉サービス加算・減算AI

障害者総合支援法に基づく障害福祉サービスのうち、以下4サービスの**加算・減算**について、要件や仕組みをチャット形式で質問できるWebアプリです。

- 施設入所支援
- 生活介護
- 短期入所(ショートステイ)
- 共同生活援助(グループホーム/旧:共同生活介護)

国保連への請求実務(加算の算定可否判断、要件確認)を支援することを目的としています。

## できること(現バージョン)

- チャットで「〇〇加算の要件は?」「〇〇加算の仕組みは?」のように質問すると、関連する加算・減算の要件・単位数の目安・注意点・確認先を回答
- サービス種類ごとの加算・減算一覧をサイドバーで閲覧
- 加算をクリックし、要件チェックリストに回答すると簡易的に算定可否を判定(自動判定機能の第一段階)
- `ANTHROPIC_API_KEY` を設定するとClaude APIによる自然文回答(社内ナレッジベースの範囲内でのグラウンディング回答)に切り替わり、未設定の場合はテンプレートによる回答にフォールバック

## 重要な注意事項(必ずお読みください)

- 本アプリの加算・減算データ(`data/services/*.json`)は、**一般的な制度知識をベースに作成した初期版**であり、厚生労働省の障害福祉サービス等報酬告示・留意事項通知の原文そのものではありません。
- 単位数・加算率は具体的な数値ではなく「要確認」としている箇所が多くあります。**実際の請求・算定判断には必ず最新の報酬告示、留意事項通知、Q&A、及び管轄の自治体・国保連への確認を行ってください。**
- 報酬改定(3年に1度が基本)により加算体系・要件・単位数は変更されるため、本データは定期的な見直しが必要です。

## セットアップ

```bash
npm install
npm start
# http://localhost:3000 で起動
```

Claude APIによる自然文回答を有効にする場合:

```bash
export ANTHROPIC_API_KEY=sk-ant-...
npm start
```

未設定でも、ナレッジベースから抽出したテンプレート形式の回答は問題なく動作します。

## ディレクトリ構成

```
data/services/           サービス種類ごとの加算・減算データ(JSON)
  common_additions.json    全サービス共通の代表的な加算(処遇改善加算等)
  common_reductions.json   全サービス共通の代表的な減算(虐待防止未実施減算等)
  shisetsu_nyusho_shien.json   施設入所支援
  seikatsu_kaigo.json          生活介護
  tanki_nyusho.json            短期入所
  kyodo_seikatsu_engo.json      共同生活援助

lib/
  dataStore.js       JSONデータの読み込み・結合
  search.js          質問文とサービス種類・加算データのマッチング(文字bigram類似度)
  eligibility.js      要件チェックリストに基づく簡易判定ロジック
  claude.js          Claude API連携(グラウンディング回答生成、任意)
  answerFormatter.js  ナレッジベースの内容からテンプレート回答を組み立て

routes/api.js         REST API (/api/services, /api/search, /api/chat, /api/eligibility/...)
public/                フロントエンド(チャットUI・加算一覧・要件チェックモーダル)
server.js              Expressサーバーのエントリポイント
```

## API

| メソッド | パス | 説明 |
|---|---|---|
| GET | `/api/services` | サービス一覧取得 |
| GET | `/api/services/:serviceId` | 特定サービスの加算・減算詳細 |
| GET | `/api/reductions` | 共通減算一覧 |
| GET | `/api/search?q=...&serviceId=...` | キーワード検索 |
| POST | `/api/chat` | チャット質問への回答(`{ message, serviceId? }`) |
| POST | `/api/eligibility/:serviceId/:additionId` | 要件チェックリストへの回答から簡易判定(`{ answers: { reqId: value } }`) |

## 今後のロードマップ

1. **データ精度の向上**: 実際の報酬告示・留意事項通知・Q&Aのテキストを取り込み、単位数や要件文言を正式なものに置き換える(RAG化)
2. **自動判定機能の拡充**: 現在は加算単位の簡易チェックのみだが、利用者・事業所の実データ(職員配置実績、利用者の障害支援区分等)を入力として複数加算を横断的に自動判定できるようにする
3. **地域差・自治体独自ルールへの対応**: 都道府県・市町村ごとの運用の違いを反映
4. **改定履歴の管理**: 報酬改定(3年ごと)に応じたデータのバージョン管理・差分表示
