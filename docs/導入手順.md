# 導入手順(勤務変更申請・承認システム)

このシステムは Excel マクロ(VBA)だけで動作し、追加のサーバーは不要です。
共有フォルダに置いた1つの Excel ファイルを、各PCから開いて使います。

## 全体像

- `output/勤務変更管理システム.xlsx` … テンプレート本体(シート構成・数式・書式は完成済み)
- `vba/*.bas` … マクロのソースコード(Excel にインポートして使う)
- `vba/ThisWorkbook.txt` … `ThisWorkbook`(ブック自体のイベント)に貼り付けるコード

テンプレートに実際のマクロを組み込む作業(下記手順1〜4)は、Excel の VBA エディタ上でしか
行えないため、最初の1回だけ Windows + Excel の環境で手作業が必要です。

---

## 手順1. マクロ有効ブックとして保存

1. `output/勤務変更管理システム.xlsx` を Excel で開く
2. 「ファイル」→「名前を付けて保存」→ファイルの種類を **「Excel マクロ有効ブック (*.xlsm)」** に変更して保存
   - 例: `勤務変更管理システム.xlsm`

## 手順2. VBAモジュールのインポート

1. `Alt + F11` で VBA エディタを開く
2. 左側の「プロジェクト」ウィンドウで対象ブックを右クリック →
   「ファイルのインポート」を選び、以下を **すべて** インポートする
   - `vba/modCommon.bas`
   - `vba/modSecurity.bas`
   - `vba/modRequest.bas`
   - `vba/modApproval.bas`
   - `vba/modRollback.bas`
   - `vba/modSetup.bas`
   - `vba/modSwap.bas`
   - `vba/modLeave.bas`
   - `vba/modOvertime.bas`
   - `vba/modImport.bas`
   - `vba/modChoices.bas`
   - `vba/modMonthly.bas`
3. 左側の「Microsoft Excel Objects」→「ThisWorkbook」をダブルクリックして開き、
   `vba/ThisWorkbook.txt` の中身をそのままコード欄に貼り付ける

## 手順3. マクロを有効にする設定(共有フォルダ運用向け)

共有フォルダ(ネットワークパス)上の Excel ファイルは、既定では
「保護ビュー」やマクロブロックの対象になることがあります。以下のどちらかを設定してください。

- **推奨**: 「ファイル」→「オプション」→「セキュリティセンター」→
  「セキュリティセンターの設定」→「信頼できる場所」で、共有フォルダのパスを
  信頼できる場所として登録する(各PCで1回設定)
- 簡易対応: ファイルを開くたびに黄色い警告バーの「コンテンツの有効化」を押す
  (押し忘れるとボタンが動作しません)

## 手順4. 保存してブックを再オープン

一度保存してファイルを閉じ、再度開き直してください。
`ThisWorkbook` の `Workbook_Open` が実行され、シート保護・入力規則(ドロップダウン)・
各シートのボタンが自動的に整います。

---

## 手順5. 職員(申請者・承認者)の登録

1. `Alt + F8` でマクロ一覧を開き、`RegisterStaff` を実行
2. 氏名を入力 → 承認権限の有無を選択(上司にあたる人は「はい」を選ぶ)
3. パスワードを2回入力(半角英数字を推奨)
4. 登録したい職員の人数分、これを繰り返す

パスワードは平文では保存されず、職員ごとに異なる「ソルト」を付けた
SHA-256 ハッシュ値のみが `職員マスタ`(非表示シート)に保存されます。

> 承認権限を持つ職員は「一般・承認者」として登録してください。
> 承認だけでなく、変更の取り消し(ロールバック)にも同じ承認権限が必要です。

パスワードを本人が変更したい場合は `Alt+F8` → `ChangeMyPassword` を実行してください。

## 手順6. シフト表への実データ入力

このシステムは部署ごとに「シフト表_入所」「シフト表_上司」「シフト表_通所」「シフト表_事務局」
のようなシートを持ちます(部署名は `tools/build_workbook.py` の `DEPARTMENTS` を編集して
自由に変更・追加できます)。実データの入れ方は2通りあります。

**方法A: 既存Excelシフト表から取り込む(推奨)**

1. `設定` シート(非表示。VBAエディタの「プロジェクト」から表示するか、
   シート見出しを右クリック→再表示で `設定` を選択)の `B1` セルに、
   対象年月の1日の日付を入力(例: 2026/8/1)
2. `Alt+F8` → `ImportShiftTable` を実行
3. 案内に沿って、取り込み先の部署 → 元のExcelファイル → 元ファイルのシート名 →
   職員の行が並んでいる開始行・終了行、の順に入力する
   - 日付(1〜31日)がどの列にあるかは自動検出されるが、職員の行範囲は
     必ず人の目で確認して入力する(集計行や別グループの表を誤って
     取り込まないようにするため)
   - 同じシートに複数の職員グループ(表)がある場合は、このマクロを
     グループの数だけ繰り返し実行する
   - 元ファイルがパスワード保護されている場合は、先に保護を解除して
     保存したファイルを指定する
4. 取り込み完了後に表示される一覧と、実際に `シフト表_〇〇` シートの内容を
   見比べて、正しく取り込めているか必ず確認する

**方法B: 手入力する**

1. 対象の `シフト表_〇〇` シートに、A列へ職員氏名、B列以降(1〜31日)へ
   当月のシフト内容を直接入力する
   - このシートはシート保護がかかっていますが、`ApplyProtection` は
     `UserInterfaceOnly:=True` のため、マクロ経由の書き込みは可能です。
     直接手入力で大量に書き換える場合は、シート右クリック→「シート保護の解除」
     (パスワード: `vba/modCommon.bas` の `SHEET_PROTECT_PASSWORD`)を一時的に行ってください。
2. 入力後、必ずシート保護を再度かけ直してください(手作業で解除した場合)。
   `Alt+F8` → `ApplyProtection` を実行すれば自動で再保護されます。

**共通の注意点**

- どちらの方法でも、A列の氏名は `RegisterStaff` で登録する氏名と
  **1文字1文字まったく同じ**にしてください(取り込み機能は氏名の前後・間の
  スペース(全角・半角とも)を自動的に取り除きますが、それ以外の表記ゆれ
  (旧字体・新字体の違いなど)は自動では直りません)。

> **個人情報の取り扱いについて**: このリポジトリのテンプレートには
> 実在する職員名は含めていません(サンプル名のみ)。実際の職員名・シフト内容を
> 入力したファイルは、個人情報を含む業務データです。Gitリポジトリなど
> ソースコード管理には含めず、共有フォルダ側でのみ管理してください。

## 手順7. 共有フォルダへの配置

1. 完成した `.xlsm` ファイルを、職場の共有フォルダ(NASや社内共有ドライブ)に配置
2. 各PCからは、そのファイルへのショートカットを作成しておくと便利です

## 日常の使い方

日付・開始時刻・終了時刻の欄は、セルをクリックすると右側に▼が表示され、
一覧から選ぶだけで入力できます(対象年月の日付一覧、15分刻みの時刻一覧)。
一覧にない日付・時刻を直接入力することもできます(警告は出ますが止まりません)。
日付の一覧の中身は「設定」シートの対象年月(`B1`)をその場で参照しているため、
対象年月を変更すると、ファイルを開き直さなくても即座に一覧の日付が切り替わります。

### 申請する側(部下)

**単独の勤務変更(自分の勤務を変える)**

1. ファイルを開き「申請」シートへ移動
2. 氏名・パスワード・対象日・変更後の勤務内容・(任意)理由を入力
3. 「申請する」ボタンを押す → 申請IDが発行され、「履歴」シートに「申請中」として記録される

**2名間の勤務交換(振替)**

1. 「交換申請」シートへ移動
2. 申請者氏名・パスワードを入力(申請する本人の認証)
3. 【対象者A】【対象者B】それぞれについて、氏名・対象日・変更後の勤務内容を入力
   (現在の勤務は氏名と対象日を入力すると自動表示される)
4. 必要なら交換理由を入力し、「交換を申請する」ボタンを押す
   → 同じ申請IDで、対象者Aと対象者Bそれぞれの変更が1件ずつ履歴に記録される
   (誰が申請したか=申請者、誰の勤務が変わるか=対象者、として別々に記録されるため、
   「誰の申請で・誰と誰の・どんな変更か」が履歴上で具体的に確認できる)
5. 承認・却下・ロールバックは、同じ申請IDに紐づく対象者Aと対象者Bの変更が必ず
   セットで処理される(片方だけ反映される、片方だけ取り消されるということはない)

**有給休暇の申請(連続した日付範囲をまとめて申請)**

1. 「有給申請」シートへ移動
2. 申請者氏名・パスワードを入力
3. 開始日・終了日(1日だけの場合は同じ日を両方に入力)・(任意)理由を入力
4. 「有給を申請する」ボタンを押す
   → 開始日〜終了日の全日程が、同じ申請IDで履歴に1行ずつ記録される
   (承認・ロールバックも全日程がまとめて処理される)
5. 承認されると、対象期間のシフト表のセルが有給の勤務コード(既定は「年」。
   「設定」シートのB4セルで変更可能)に置き換わる

**超過勤務(残業)の申請**

1. 「超過勤務申請」シートへ移動
2. 申請者氏名・パスワード・対象日・開始時刻・終了時刻・(任意)理由を入力
3. 「残業を申請する」ボタンを押す
   → 残業時間が自動計算され、履歴に記録される
4. 承認されると、シフト表の対象日のセルの末尾に残業時間が追記される
   (例: 「日勤」→「日勤(残1時間30分)」。元の勤務コード自体は消えない)
5. ロールバックすると、追記される前の元の勤務コードに戻る

### 承認する側(上司)

1. 「承認」シートへ移動すると、下部に承認待ち一覧が自動表示される
2. 対象申請ID・自分の氏名・パスワード・判定(承認/却下)を入力
3. 「承認/却下を実行」ボタンを押す
   - 承認 → シフト表に即時反映され、履歴に承認者名と承認日時が記録される
   - 却下 → シフト表は変更されず、履歴に却下として記録される

### 履歴の確認

- 「履歴」シートに、申請から承認・却下・取り消しまで **すべての操作が時系列で記録**されます
  (申請ID・申請者・対象者・対象日・変更前後の内容・ステータス・承認者・承認日時)
- 「申請者」(誰が申請したか)と「対象者」(誰の勤務が変わるか)は別の列で管理されるため、
  代理申請や交換申請でも「誰の申請で・誰の勤務がどう変わったか」を具体的に確認できます
- 交換申請は同じ申請IDの行が2行(対象者A分・対象者B分)続けて記録されるため、
  1件の申請で「誰と誰の」変更だったかが履歴上でも一目でわかります
- オートフィルターで職員名やステータスによる絞り込みが可能です

### 元に戻す(ロールバック)

1. 「ロールバック」シートへ移動すると、承認済みの変更一覧が自動表示される
2. 取り消したい申請ID・承認権限者の氏名・パスワードを入力
3. 「選択した変更を取り消す」ボタンを押すと、シフト表が変更前の内容に戻る
   - この取り消し操作自体も新しい履歴として記録されるため、
     「誰が・いつ・どの申請を取り消したか」も後から確認できます

### 月初めの切り替え(管理者向け)

月が変わるタイミングで、職員マスタ(氏名・パスワード)はそのまま残し、
各部署のシフト表の中身(職員名・シフト内容)だけをまとめてリセットできます。

1. 「管理」シートへ移動
2. 「月初めの切り替え」ボタンを押す
3. 新しい対象年月の1日を入力(例: 2026/10/1)
4. 内容を確認して「はい」を選ぶ
   → 「設定」シートの対象年月が更新され、各部署の「シフト表_〇〇」シートの
     中身(職員名・シフト内容)がすべて消去される(履歴・職員マスタは変更されない)
5. 続けて `ImportShiftTable`(取り込み)または手入力で、新しい月のシフトデータを入力する

**運用のおすすめ**: 月ごとに別ファイルとして保存し(前月のファイルをコピーして
新しい月のファイル名で保存)、そのコピーの中でこの「月初めの切り替え」を実行する
形がおすすめです。職員登録をやり直す手間なく、前月分のファイルはそのまま
その月の記録として保管できます。

## 運用上の注意(重要)

- **同時編集について**: Excel ファイル1つを共有フォルダ経由で使う方式のため、
  複数人が同時に「編集モード」で開くと、後から保存した内容で上書きされる
  可能性があります。申請・承認操作を行う人以外は「読み取り専用」で開くことを
  推奨します。同時アクセスがどうしても頻発する場合は、将来的にデータベース+
  Webアプリ方式への移行を検討してください。
- **パスワードの表示について**: パスワード入力欄はセル・InputBoxとも
  画面上でマスク(●●●表示)されません。周囲から見えないよう入力時にご注意ください。
- **シート保護パスワードについて**: 各部署の `シフト表_〇〇`・`履歴` シートにかけている
  シート保護は「誤操作防止」のためのものであり、真のアクセス制御ではありません。
  実際の承認権限は、職員マスタに保存されたパスワードハッシュの照合で判定しています。
- **マクロが動かない場合**: セキュリティセンターの設定でマクロがブロックされていないか、
  「コンテンツの有効化」を押し忘れていないかを確認してください。
- **バックアップ**: 履歴シートに全操作が残りますが、ファイル自体の破損に備えて
  共有フォルダ側の世代管理(NASのスナップショット機能やバックアップソフト)も
  あわせて運用することを推奨します。
