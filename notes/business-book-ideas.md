# ビジネス本 アイデアメモ

いずれ出版するビジネス本のために、思いついたことをここに随時書き足していく。

## 使い方

- 思いついたことを都度「メモ」セクションに追記する（日付つき）。
- 内容が固まってきたら、テーマごとに「章立て候補」に整理する。
- 不明点・要確認事項は「要確認」に残しておく。
- すでに完成した原稿・コラムは断片メモと分けて `notes/columns/` 配下に1本ずつファイルとして保存し、「原稿・コラム一覧」に登録する。

## 章立て候補

- 組織の振り子（揺り戻し）：優しさと厳しさのマネジメント
  - 「優しくする」路線：職員が辞めないようにやさしくする、ミスを許容する
    - メリット: 退職率が下がる
    - デメリット: 職員が成長しない、トラブルを起こしやすくなる
  - 「厳しくする」路線：↑の反対の結果が起こる
    - メリット: 成長する、トラブルが減る（と考えられる）
    - デメリット: 退職率が上がる
  - どちらかに振り切ると副作用が出る＝組織はフラットな正解がなく揺り戻しが起きやすい
  - 結論（暫定）: その時々で「今、良いと思うこと」を考えて実施していくしかない
    - ただし「今の最善」が「中長期の最善」であるとは限らない
    - 未来は読めない。それでもやっていくしかない、というのがリーダーの現実

- リーダーは「自分のコピー」を作りたがる
  - リーダーは自分の成功体験（自分が育ってきた過程）を基準にしてしまう
  - 「部下は自分と同じようにあるべき」と無意識に思い込みがち
  - しかし本来、リーダー像は世代やその人個人によって変わるもの
    - 表現案: 昭和のリーダー像 vs 令和のリーダー像を対比表で示すとわかりやすい（たたき台。実体験に合わせて要調整）

      | 観点 | 昭和のリーダー像 | 令和のリーダー像 |
      |---|---|---|
      | 伝え方 | 背中で見せる。多くを語らない | 言語化する。理由や意図を説明する |
      | 育成方法 | 見て盗め・経験させる（根性論） | 教える・仕組み化する（心理的安全性重視） |
      | ミスへの対応 | 叱る・詰める | 原因を分析し、次に活かす |
      | 労働観 | 滅私奉公、残業・休日出勤は当然 | ワークライフバランス、効率・成果重視 |
      | 評価基準 | 年功序列、忠誠心・従順さ | 成果・スキル、公平性・納得感 |
      | リーダーの立ち位置 | カリスマ・絶対的存在（トップダウン） | 伴走者・ファシリテーター（対話重視） |
      | 情報共有 | 必要な情報だけ、トップダウン | オープン・透明性重視 |
      | 距離感 | 上下関係が明確、飲みニケーションで結束 | フラットな関係、プライベートと仕事は分離 |
      | モチベーション源 | 会社への忠誠、出世 | 自己成長、働きがい、納得感 |

      - どちらが正しいという話ではなく、リーダー自身が育った時代の当たり前を、無意識に部下に押し付けてしまう、という点がポイント
  - 大事なのは「自分と同じかどうか」ではなく「組織がうまくいくかどうか」
    - 自分と同じであることは正解ではない
    - 在籍する職員の人数・能力・性格によっても、最適なマネジメントは変わる
  - 実践的な結論: 大事なことを伝えるのは良いが、「自分と同じでない」という理由で怒るのはやめた方がいい
  - 実体験エピソード: 「自分の『得意』に気づいたきっかけ」（→エピソード集を参照）

- 気配りは能力。ただし、気配りしすぎない
  - キャッチフレーズ案: 「あえて気配らないという気配り」
    - 気を配った上で、あえて手を出さない・口を出さないこと自体が、高度な気配りである、という逆説
  - 気配りができることは、それ自体が一つの「能力」
  - しかしリーダーが気を配りすぎて、自分で何でもやってしまうと
    - 周りの職員の「仕事」を奪ってしまう
    - 職員が気配りの能力・経験を積む機会も奪ってしまう
  - 本来大事なのは、自分が気を配って自分で動くことではなく、気を配った上で「他の職員を動かす」「他の職員自身に気を配らせる」こと
    - ＝気配りの目的は「自分がやること」ではなく「人に任せること」
  - 実践的な結論: 何でも自分でやらない。ミスが出ないように先回りしすぎない
  - 「自分のコピーを作りがち」「気配りしすぎない」はどちらも“リーダーが自分でやりすぎることの弊害”という同じ根っこの話として繋げられそう
  - 実体験エピソード: 「気配りしすぎて自分依存の組織を作ってしまった」（→エピソード集を参照）
  - 注意点・リスク: 「あえてやらないという気配り」は、サボりたい人の言い訳に悪用されうる
    - 本人のため・周囲のため・組織のためを思っての「あえてやらない」であれば許される
    - 一方、単に楽をしたいだけの「やらない」と、意図的に見極める必要がある
    - そもそも、その見極めができない・言い訳にしてしまう人は、管理職やより上の役職に上げるべきではない
    - ＝「あえてやらない気配り」を機能させるには、それにふさわしい人を選ぶ人事制度・登用基準も必要になってくる

- 行動して失敗する人を評価する
  - 「行動を起こして失敗する人」と「何も行動を起こさず、失敗も成功もしない人」がいる
  - 行動を起こす人は、成功に至るまでの過程でミスも多くなる
  - そのミスだけに着目して怒っていたら、誰も行動を起こさなくなる
  - 評価するなら、何もしない人よりも、行動して失敗する人を評価したい
  - 行動して失敗した人を注意するなら、何もしない人にもある程度注意すべき
    - どちらかというと、何もしない人の方が罪が重い気がしている
    - ただし、これを明確な評価基準・ルールとして設ける必要はない
  - 明文化したルールというより、風土・文化として「行動してミスをすることは悪いことではない」を根付かせたい
  - ミスは誰しもしたくないものだが、ちゃんと考えて行動した結果のミスであれば
    - その責任は本人に取らせず、上司が取るべきものだという認識を組織に植え付け、定着させたい
    - それによって、職員が失敗を恐れずに行動できるようにしたい
  - 「組織の振り子」（ミスの許容）「気配りしすぎない」（任せることでミスも増える）とも繋がるテーマ
  - 実体験エピソード: 「ズボンの裾上げ」（→エピソード集を参照）

- 若手時代、会議で「譲歩ライン」を決めて臨む
  - 若い頃、会議や意見交換の場に臨む姿勢として、自分の立場（意見）を決め、そこから「最低限、譲歩してもいいライン」を事前に決めておき、「ここからは絶対に引かない」という気持ちで臨んでいた
  - 特に、一人で大勢の人たちに向かう時に、この考え方で取り組んできた
  - 周りには上司や経験年数が上の、声の大きい人が多い中で、自分から進んで発言し、後ろに下がらないという決意をしていた。時には（決めたラインまでは）折れる必要もあったかもしれない
  - これは若いからこそ許される方法かもしれない
  - デメリットの多いやり方かもしれないが、メリットもある。それを経験することで学べることも多く、やる価値も少なからずあると思う

- あえて反対意見を言う：会議の論点を増やすための意見聴取術
  - 会議で意見を聴取する際、できるだけ偏った意見にならないようにしている
  - 自分がそう思っていなくても、バランスを取るために、あえて違う視点を持ち込む
  - 目的は「自分の意見を通すこと」ではなく「会議の論点を増やすこと」
  - これを意識的に実践している

- 現場を離れたら、口を出しすぎない。自分の経験を絶対視しない
  - 昔は現場の支援員として、バリバリ仕事をしていた
  - 現場を離れて上司（管理職）になってからは、「現場のことを知らないのだから、（安易に）口出しをしない」ということをしてきた
  - 相談されれば話す・アドバイスはするが、一場面だけ見た・一緒に見ただけの偏った情報だけで判断して、ギャーギャー（感情的に）言うことはしないようにしたい
  - 昔の経験は確かに重要な面もある
  - しかし、その経験・やり方が今の状況にとって最適かどうかは分からないので、注意すべき
  - 「自分はこうだった。だからこれが正しい」という言い方はやめた方がいい
  - 「自分のコピーを作りがち」「あえてやらない気配り」とも繋がるテーマ（過去の自分・自分のやり方を絶対視しない）

- 難しい利用者こそ自分がまず対応する
  - 現場の支援員時代、対応の難しい利用者ほど、まず自分が対応するようにしていた
  - いろんなことを試し、失敗もし、成功もして、分析材料をたくさん出す
  - それが後々の支援（その利用者への支援・組織としてのノウハウ）に生きる
  - 「行動して失敗する人を評価する」「難しい利用者への対応を任せるようになった」（→エピソード集「気配りしすぎて自分依存の組織を作ってしまった」）とも繋がるテーマ

- 問題がある職員には、個人にではなく全体に言う
  - 問題がある職員がいた時、まずはその個人に直接言うのではなく、全体に向けて伝える
  - 理由: 問題に見える場面では、他の職員も同様の対応をしていることが多い。その状況で個人だけを名指しすると「自分ばかり言われた」という不満が生まれるため、それを避けたい
  - 欠点: 全体に向けて言うと、本人が「自分に言われていること」だと自覚せず、伝わらないことがある
  - 「感情で動かない、感情を理解して動く」で触れた「不機嫌を許さない仕組み、ルールにする」（個別対応ではなく仕組み化する発想）とも繋がるテーマ

- 支援に100点はない：見る人によって「正解」が変わる
  - 100点の支援というものは存在しない
  - 支援は一方的に与えるものではなく、相互関係の中で成り立つ支援もある
  - 「誰から見て100点か」という価値観も、立場によって異なる
    - 利用者本人から見た100点
    - 職員から見た100点
    - 人権を重視する立場（人権擁護の観点）から見た100点
    - リスク管理を重視する立場から見た100点
    - 保護者から見た100点
    - 事業所（現場）から見た100点
    - 法人（組織全体）から見た100点
    - 上司から見た100点
  - これらの「100点」は必ずしも一致しない。ある立場での100点が、別の立場では0点に近く見えることもありうる
  - 参考資料: 「心理的虐待とネグレクトの具体例(対比表)」（→資料を参照）。対応が厳しすぎる／甘すぎる（放置）、それぞれの極端な例を示しており、「組織の振り子」の話とも直結する
  - 具体例: 「入所判断のジレンマ（経営と安全のバランス）」
    - 利用者の入所を判断する上でのポイント
      - 空きがある状態は、経営面でダメージになる
      - だからといって、他害（他人に危害を加えるおそれ）のある方を無理に入所させると、他の利用者の満足度・安心感が下がる
      - この対立をどこで折り合いをつけるかが問題であり、どちらを選んでも誰かの不満は必ず出る
    - 対応としてできること
      - 完全な正解はないので、中間地点を探る
      - 上司にも部下にも、それぞれに合った形で詳しい情報を共有する
        - 部下には「空きがあるとボーナスが下がる」といった経営の実情を伝える
        - 上司には「今入所させると事故のリスクが上がり、結果的に訴訟リスクにつながる」といった現場のリスクをしっかり説明する
      - 大事なのは「全員が納得しないと物事を進められない」ということではなく、しっかり説明し、情報共有する努力をすること（説明責任を果たす）

- 観察とシミュレーションの習慣：引き出しを増やす自己研鑽法
  - 利用者の行動をよく観察することが大事
    - どういう行動があるかをしっかり見極め、その人のパターンや推測を積み上げていく
    - ABA（応用行動分析学）的な要素もあり、「人間はこうだから、こう動きがち」という知識も持っておくと、いざという時に対応できる職員になれる
  - シミュレーション（空想）の習慣も重要
    - 利用者の見守りをしている中で、明確な用事がない時間には、あえて空想をする
    - 例: もし今火事が起きたら／夜勤中に何かが起きたら／利用者の誰かが暴れ出したら、それぞれどう対応するのが良いか、といった様々な想定をする
    - この習慣づけが「引き出し」を増やす
  - 引き出しが多いと、全く同じ状況が起きなくても、当てはめたり応用したりすることができ、実際の対応につながる
  - 具体例: 災害対応
    - 災害時は、マニュアルが通じないことが前提
    - 災害は想定通りには起きないからこそ、訓練が必要
    - マニュアル通りに起きる災害はないので、平時からいかに「引き出し」を作っておくかが大事

- 自分の何気ない行動が、他者の業務を阻害することがある
  - おしゃべりや独り言を、悪気なく何気なくしてしまうことがある
  - しかしそれは、他者の業務効率を下げていることがある。特に事務分野（集中を要する仕事）では影響が大きい
  - それを頭に入れた上で、自分がどういう行動をすべきか考える
  - キャッチフレーズ案: 「おしゃべりや独り言は、他者の残業時間を作る行動」と認識する

- 動かずに文句を言うなら、自分にも一端の責任がある
  - 自分が動かないことによって悪いことが起きると予測される時は、動くようにする
  - 動くことには勇気がいるし、失敗もある
  - 一方、動かずに現状にぶつぶつ文句を言うことは、自分にも責任があると考える
    - やるべきことをしていない以上、自分もその問題の一端を担っていると考える
  - 文句を言うのは、まず自分がやるべきことをしてからにしようと思う
  - 「行動して失敗する人を評価する」と表裏一体のテーマ（行動しない人・文句だけ言う人への自戒）

- 「事業所都合の善」が生む矛盾：遅刻はダメ、早出はOKの不公平
  - 遅刻は許されないのに、早く来て（勤務時間前から）仕事をすることはおかしいと思われない
  - しかし本来、どちらも「悪いこと」として認識すべき
  - 事業所（会社）にとって都合がいいことを「善」としてしまうと、こういう矛盾した考え方になる
  - それが組織に蔓延すると、不平不満やモチベーションの低下、パフォーマンスの低下につながる

- 「自分は大したことない」という気持ちを持ち続ける
  - 心のどこかに、少しでもいいので「自分は大したことない」という気持ちを常に持っている
  - それがあることで、言動・行動、周りからの印象だけでなく、自分自身を見つめ直し、常に成長できる部分を探すことに繋がる
  - 逆に、自分に問題・欠点がない（完璧だ）と思ってしまうと、成長しようとは思わなくなる
  - 「自分の『得意』に気づいたきっかけ」（→エピソード集）、「得意を伸ばし苦手を減らす、改善する気持ちをなくさない」（→自分のコピーを作りがちの補足）とも繋がる、この本全体の土台になる考え方

- AI全盛期だからこそ、あえてアナログを使う：道具は使う人の力で変わる
  - AIが全盛の時代だからこそ、あえてアナログを使う
  - AIを使いこなすにも、もともとの人間力や能力が必要
  - 道具（もの）は、いつもどこでも「使う人の力」によって結果が変わる
    - 例: ペンを持っても、いい文章が書ける人と書けない人に分かれる。きれいな字が書ける人と汚い字になる人に分かれる
  - こうした基礎的な能力の重要性を認識し、それを身につけさせる取り組み・考え方を持つ
  - 一方で、道具・進化を過剰に否定するものではない、という補足
    - AIは、昔でいう「そろばん」や「電卓」のようなもの。車でいえば「バックモニター」や「ナビ」のようなもの
    - それによって衰える能力もあるかもしれないが、人間が道具を使うとはそもそもそういうことであり、それによって人類は進化してきた
      - 例: 徒歩 → 飛脚 → 自転車 → 車 → 電車 → 飛行機（移動の進化）
      - 例: 移動しなくても連絡が取れる電話 → 常に携帯できる携帯電話 → 文字で連絡できるスマホ（通信の進化）
    - それを踏まえると、モノやAIを過剰に嫌うことは、結果的に組織・事業所として支援の質を下げる行為に繋がるかもしれない、という意識を持つ
    - ＝「基礎的な能力を身につける」ことと「新しい道具・AIを取り入れる」ことは対立しない。両方を意識する必要がある

### 心理的虐待とネグレクトの具体例（対比表）

介護・福祉の現場で、対応が「厳しすぎる（心理的虐待に近づく）」場合と「甘すぎる・放置（ネグレクトに近づく）」場合の、それぞれの極端な具体例。「組織の振り子」「支援に100点はない」の章の参考資料として、2026-09-21にアップロードされたExcelファイルより転記。

| 心理的虐待（積極的な言動） | ネグレクト（必要な対応の放置） |
|---|---|
| 言葉による攻撃：暴言や人格否定 | 食事の放置：介助不足、水分補給を怠る |
| 拒絶や無視：返事をしない、存在を無視する | 衛生の放置：入浴・着替え・排せつ介助の頻度不足 |
| 脅しや威圧：怒鳴る、怖がらせる態度 | 医療的ケアの放置：体調不良の聞き流し、受診・服薬管理の怠慢 |
| 利用者間差別：特定の利用者を著しく厳しく扱う | 見守りの放棄：転倒・危険行動リスクがある利用者から目を離す |
| 他利用者の前での威圧：見せしめ的な叱責 | 転倒リスクの放置：リスクを把握しながら環境整備・介助をしない |
| 侮辱的な呼び方・扱い：幼児言葉、渾名や番号で呼ぶなど尊厳を傷つける対応 | 送迎・帰宅時の情報伝達不足：リスクを家族・在宅側に引き継がない |
| 意思決定の無視：本人の意向を確認せず職員都合で予定を決めつける | 居室環境の放置：室温管理・危険物放置など安全配慮の欠如 |
| 交流の制限：理由なく家族面会や他利用者との交流を制限し孤立させる | 他職員への丸投げ：担当業務の放棄 |
| 執拗な叱責・嘲笑：失敗を繰り返し責める、人前で笑いものにする | 利用者間トラブルの放置：相性の悪い利用者を配慮なく同じ空間に置く |
| 存在の無視：本人がいる場で職員同士だけで会話し蚊帳の外に置く | トラブルの予兆の見逃し：険悪な様子を把握しながら見守らない |
| 脅すような言葉かけ：「言うことを聞かないと施設を出てもらう」等 | 制止の遅れ・不在：言い争いに気づきながら介入が遅れる |
| せかす・急かせる圧迫：威圧的に急かし精神的に追い詰める | 再発防止の未実施：トラブル後の見直しをせず放置する |

## エピソード集

具体的な実体験。各章の実例として使う。

### ズボンの裾上げ（「行動して失敗する人を評価する」の実例）

- 昔、利用者のズボンの丈が長すぎるという問題があった
- 周りの職員は、めくったり畳んだりして対応していた
- 恭成は、下手なりにミシンを使って裾上げをした
  - 裾上げの出来は下手で、ボロボロで見栄えも悪かった
  - しかし、畳んだだけでは歩いているうちに裾が垂れてきて、それが引っかかって転倒するリスクがあると考え、それを防ぐために行動した
- その行動（見た目の悪さ）に対して文句を言われた
  - こういう対応をされると、やる気をなくす人は多いと思った
  - 「（文句を言った）分かってない上司だな」と感じた
  - 自分はそうならないようにしようと決意した
- ※「転倒のリスク」の意味で書かれていると解釈しました（原文は「店頭のリスク」）。違っていれば教えてください。

### 自分の「得意」に気づいたきっかけ（「リーダーは自分のコピーを作りたがる」の実例）

- 昔は、自分のようなことができない人はダメだと思っていた
  - 自分ができているのに、なぜ周りはできないのかと思っていた
- しかし、よく考えると自分だけで組織が成り立っているわけがないと気づいた
  - 周りの人がフォローや配慮をした行動をしてくれるおかげで、自分は進んで前に立てていた
- 自分は前に進む（推進する）ことは得意だが、フォローに回ったり待ったりすることは苦手
  - 自分は自分の得意なことで輝けたり進めたりできるから良いが、もし自分がフォロー役の立場に立ったら、能力を発揮できなかったはず
- 自分の能力が高いから活躍できたわけではなく、結局は自分に合った「いる場所」が良かっただけだと思った
  - 人にはそれぞれ得意な場所・抱えている場所があり、それのおかげで組織は回っている
- 自分の周りに、うまくバランスよく動いてくれる人材が揃っていた（そういう世代・チーム構成だった）ため、自分はある程度活躍できたのではないかと思う
  - ただ単に運が良かっただけ、それに尽きるのではないかと思う
- 補足: 周りへの感謝は忘れないが、それを理由に苦手なことから目を背けてはいけない
  - 自分がやりやすい仕事・自分が心地いいだけの場所にすることはダメ
  - 「得意なことは伸ばす、苦手なことは減らす」が基本ライン
  - どうしてもダメなことは、ある程度諦める部分があってもいいかもしれない
  - ただし、改善しようという気持ちだけはなくしてはいけない

### 気配りしすぎて自分依存の組織を作ってしまった（「気配りは能力。ただし気配りしすぎない」の実例）

- 自分が出勤している時は、必ず何でも気配りをしてうまく回してやろうと思っていた
- 自分ができる範囲のことは頭をフル回転させて行動し、うまく回していた
- それを長年続けた結果、自分が出勤している時はみんなが自分に頼るようになった
  - 対応の難しい利用者への対応なども、自分に任せる（丸投げする）ようになった
- そうなると、自分がいない時は皆が困り、難しいことを他へ振る（対応を避ける）ことが習慣づいてしまったように感じた
- これは大きな反省点として、「気配りをしない」という気配りをするようにし始めた
  - 始めた当初は、つい自分でやりたいという気持ちもあった
  - しかしこれは自分の感情のためではなく、組織全体のためを思ってやるようにした
  - 結果的に良かったかどうかは判断できないが、自分で行動してくれる職員は増えたのではないかと思う
- 「あえてやらないという気配り」は逃げではなく、その人のため・周囲のため・組織のためを思った行動であれば許される
  - ただし、サボりたい人がこれを言い訳に使うこともあるので、しっかり見極められるようにしたい
  - そもそも、その見極めができない・言い訳にしてしまうような人を、管理職やより上の役職に上げる必要はないと思う
  - そういった人を選ぶための人事制度も必要になってくるのではないか
- ※「他社に投げる」という部分は、難しい対応を他の人・他部署に振る、という意味で解釈しました。意図と違う場合は教えてください。
